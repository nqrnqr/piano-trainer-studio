# 传统五线谱模式：平稳纵向跟随改进方案

供 GPT-6.1 sol 执行。制定日期：2026-10-04。修订策略：换行后平缓归位，使当前演奏行大部分时间处于相近的阅读区域。

执行记录（2026-10-04）：T0–T2 已实现；T3 的受控帧 OSMD 集成和回归已执行，原生前台运动验收仍需复验。参数、轨迹及验证限制见 [traditional-scroll-results.md](testing/traditional-scroll-results.md)。方案正文保留为验收依据。

## 1. 任务与范围

用户反馈：视口只能显示约两行乐谱时，光标从第一行进入第二行，整个画面随即大幅向上移动，上一行消失，阅读参照位置不稳定。

本任务只改善传统模式正常向前演奏时的纵向滚动。必须保留当前完整原谱、OSMD 原有换行和分页，以及现有音符、标记、连线和小节位置。

明确约束：

- 不实现“多行展开跟谱”，不复制反复乐句，不追加 Loop 副本，不裁切或重组原谱系统，不增加显示模式。
- 原谱反复、D.C./D.S. 等导航和练习 Loop 的返回行为暂时沿用现状。不能为了保证滚动单调而阻止返回。
- 光标从一行右端进入下一行左端属于正常读谱行为，无需制作跨行飞行动画。
- 保留横向连续模式的显示、滚动、缓存和位置映射行为。
- Wait / Follow / Realtime 使用相同的目标阅读区域；Wait 使用固定短动画，Follow / Realtime 可参考当前速度和本行拍数确定动画时长。不修改 MIDI、音频、计分、节拍、音符推进、Loop 范围或数据存储。
- 不升级 OSMD，不引入新运行时依赖，不重写播放协调器。
- 本文是执行计划，不代表功能已经实现或验证。

## 2. 当前代码依据

执行前重新核对工作区，以实际代码为准；保留用户已有未提交改动。

主要原因不是缺少 `behavior: 'smooth'`，而是没有明确的换行归位策略、稳定阅读区域和受控动画时长。本次改为在真实换行后触发一次平缓归位，避免按光标阈值反复启动滚动。

## 3. 用户体验规则

这里的“一行”指完整 music system。钢琴高低音谱表属于同一组，不能只保证右手谱表可见。

### 3.1 换行后平缓归位

1. 当前系统演奏期间，完成本次归位后保持稳定，不按每个音符持续上移。
2. 上一系统演奏结束、正式光标进入下一系统时，开始平缓向上滚动。即使新系统已经完整可见，只要它低于目标阅读区域，仍应归位。
3. 把当前系统顶部逐渐移到视口高度约 25%～35% 的区域，默认目标为 30%。到达后停下，给下方留出预览空间。
4. 新系统顶部已经在目标区域内且内容完整可见时，不作细碎调整。普通向前演奏时，不为精确居中而向后滚动。
5. 不因边界处 1～2 px 波动重启动画，也不因同一事件的重复回调延长动画。

### 3.2 阅读位置与预览

例如，第一、二系统都完整可见时，第一系统演奏期间不为第二系统预先移动。进入第二系统后，画面开始平缓上移，第二系统逐渐落入目标阅读区域；接下来大部分演奏时间保持稳定，同时露出更多第三系统。

这次修订替代原来的“第二行可见就不动，直到当前行后半段才预览下一行”规则。触发依据是实际换行，归位目标由当前系统决定，不由下一系统是否可见决定。

完整原谱下，换行瞬间光标仍从上一行右端移到下一行左端。本方案追求换行后平稳归位和大部分时间位置相近，不承诺换行瞬间光标高度完全不变。已演奏的上一行可以随归位逐渐离开视口，不强制保留整行历史。

### 3.3 等待与暂停

- Wait 模式仅在真实换行后开始归位，默认用约 0.65 秒的短动画；不把设定 BPM 当成用户实际速度。
- Follow / Realtime 只读当前速度和本行实际拍数，估算本行时间，选择归位时长。时间估算不驱动音乐推进，也不提前切换系统。
- 同一个正式事件或同一系统内后续音符不得重新启动已确定的归位动画。归位目标固定，动画位置可随墙钟平滑变化。
- Wait 等待时，允许完成已触发的这一次归位；稳定后不继续漂移，不因等待而向下一系统滚动。
- 用户暂停时取消未完成动画，固定当前位置；继续播放时重新计算目标。

### 3.4 视口不足与返回

- 两个系统无法同时容纳时，当前系统优先；下一系统只能部分预览是正常降级。
- 单个系统本身高于视口时，不承诺整个系统可见；使用当前光标可见性和最小必要移动，不来回追逐无法同时满足的上下边界。
- 新系统首事件若仍不可见，优先使当前演奏内容可读，必要时缩短本次纠正动画；极短系统或快速连续换行不保证能在每行停留足够久。
- 反复、Loop、主动 seek/reset 保留原有定位语义和传统返回策略。它们不受“普通向前时禁止回滚”约束。

## 4. 建议模块边界

采用小范围增量修改。建议增加 `src/render/traditional-scroll-policy.ts` 存放纯目标计算，`score-viewport.ts` 继续拥有 DOM、帧调度和生命周期。

### 4.1 系统几何

在 adapter / geometry 边界增加最小只读查询：

```ts
interface SystemBounds {
    systemId: number; // 当前排版版本内稳定，不能跨重排复用
    firstMeasureIndex: number;
    lastMeasureIndex: number;
    left: number;
    right: number;
    top: number;
    bottom: number;
}
```

约定所有传给滚动策略的长度均为滚动容器内容坐标中的 CSS px。adapter 可以先返回 SVG 几何，由 geometry 边界统一转换；禁止混用 OSMD units、SVG units、CSS px，禁止额外乘两次 zoom。

- 按 `ParentStaffLine.ParentMusicSystem` 对象身份识别系统，不按相近 Y 值猜测。
- 边界覆盖同组所有可见谱表，并核实系统图形范围是否包含加线、标题、歌词、力度等；以真实 vendor 数据验证，不能虚构 vendor 字段。
- 不用系统横向宽度或光标 X 百分比推算演奏时长；排版密度与音乐时长并不等价。横向几何仅用于定位和辅助判断导航。
- 排版完成后建立系统索引并按需缓存；不得每个动画帧遍历整首谱或查询所有音符 DOM。
- 若有多个 SVG 页面，必须确认各页到容器的偏移转换，不能只取第一个 SVG 或假定页面 Y 连续。
- 缩放、resize、全屏、换谱、布局重排后作废几何；单纯 scroll 不需要重建整个索引。

### 4.2 正式显示位置

不能使用已经预取到下一事件的 live iterator 提前触发换行归位。

优先使用与实际已绘制光标对应的位置：当前代码提供 `readPositions().painted`；正式 `performancePosition.current()` 可提供事件身份和原因。执行时核对回调顺序，确保测量光标、原谱小节和事件身份属于同一次显示提交。

`changed` 回调与 cursor.update 可能不在同一时刻，不能未经验证就把两者拼成快照。可在本次同步更新完成后的单次帧中读取一致快照，或增加小型显示提交入口；不要改变练习推进时机。

快照至少能区分：

- 普通同系统前进、普通相邻系统换行；
- 原谱反复或导航，包括同一系统内向左返回；
- Loop、seek/reset、换谱、重排；
- 仅重复调用、无正式位置变化。

导航判断不能只看 `reason === 'advance'`，原谱反复也可能属于 advance。结合原谱位置、出现身份与系统序列识别；不要把正常换行时 X 变小误判成反复。

### 4.3 纯策略输入与输出

纯策略接收视口尺寸、当前 scrollTop、当前系统框、导航类别、练习模式、只读的本行预计时长及上次状态，返回保持、目标位置与动画时长，或走旧导航定位分支。它不操作 DOM、不调用 renderer、不改 AppState。

本行时长查询复用现有小节时值、速度和独立遍历数据。若需小型辅助函数，只计算当前演奏路径上本次系统内的时段，不能移动 live iterator，也不另写一个播放引擎。估算失败可返回 null，由策略使用固定时长。

只需为本任务补充明确类型，不建立新的通用滚动框架。

## 5. 目标计算参考

以下给出可实现的默认策略；常量可在真实浏览器验证后小幅调整，并在交付记录中说明。

### 5.1 可见区域与迟滞

- 以 `clientHeight` 为可用高度，并正确扣除容器边框；若有覆盖在谱面上的固定控件，再扣除实测遮挡。
- 初始上下安全边距各 `clamp(0.04 * H, 12, 32)` CSS px。
- 设置约 2～4 CSS px 的迟滞，避免浮点值和缩放误差反复触发。
- 目标阅读带默认为系统顶部位于 `[0.25H, 0.35H]`，目标中心为 `0.30H`；安全边界优先于阅读带。
- 已在阅读带且整个系统安全可见时保持位置。不再使用光标顶部的 60% 阈值。

### 5.2 归位目标

令当前系统为 `[T, B]`，视口高度为 `H`，安全边距为 `pt / pb`，当前滚动位置为 `S`：

```text
阅读带中心对应位置 = T - 0.30 * H
当前系统完整可见的下界 = B - H + pb
当前系统完整可见的上界 = T - pt
合法滚动范围 = [0, scrollHeight - clientHeight]
```

当完整可见区间与合法滚动范围存在交集时，将阅读带中心对应位置裁剪到交集内，得到候选目标。目标约束优先级为：当前系统完整可读、合法滚动范围、阅读带中心。

- 真实普通换行时，新系统若位于阅读带下方，即使已经完整可见，也平滑移向候选目标。
- 已在阅读带且完整可见时保持 `S`；已在阅读带上方但仍完整可见时，也保持 `S`，不为对齐 30% 向后滚动。
- 当前内容被裁切时，按可见性作必要纠正；这与普通向前归位分开分类，不能用禁止回滚掩盖不可读问题。
- 同一系统内，已确定的目标不随音符位置重新计算；resize、重排、恢复跟随或可见性异常属于明确的重新评估入口。
- 第一页受顶部限制、末页受底部限制时，接受可达到的位置，不人为增加空白或更改谱面排版。
- 当前系统太高、边距使可见区间为空或几何缺失时，单独采用光标可见性降级，不对空区间直接 clamp。

### 5.3 动画时长与滚动速度

系统的音乐长度由实际时值决定，不由谱面宽度决定。Follow / Realtime 可对当前系统内本次经过的时段求和，使用与播放一致的有效速度：

```text
本行预计时长 Tline = Σ(每个时段的四分音符拍数 * 60 / 该时段有效四分音符 BPM)
归位时长 D = clamp(0.20 * Tline, 0.40, 1.20) 秒
平均滚动速度 = abs(目标 scrollTop - 起点 scrollTop) / D
```

- 初始比例为 20%，可在 15%～25% 内调试；时长上限与下限也需在真实曲谱上验证，结果文档记录最终值。
- 对拍号变化、弱起、休止、附点、连音和跨行延音，使用既有实际时值语义；不能直接用“小节数 × 拍号”或逐音符长度相加，多声部会重复计算。
- 核对项目现有 BPM 单位、速度覆盖和速度百分比语义。复用播放的换算，不把八分音符拍的速度标记当作四分音符 BPM，也不重复应用速度倍率。
- 只估算本次系统内到下一次离开系统前的时段，不把后续反复轮次累计进来。复杂跳转若无法可靠估算，使用默认时长。
- Wait 固定使用初始值 0.65 秒。其他模式缺少可靠时值/速度、估算为非正数或非有限数时，也回退到 0.65 秒。
- 换行时采样速度并确定本次 D；同系统内改速度不重启动画，下一次换行使用新速度。后续如需动态调速，另行提出，不扩大本次范围。
- 动画以实际移动距离和 D 生成速度曲线，采用有缓入缓出的有限时长插值，例如 smoothstep；不要按固定 px/帧运行。
- 很短一行可能在归位完成前就结束：新系统接管未完成动画，从实际位置改向新目标，不排队补播，不强制等待动画完成才能演奏。
- 大距离跨页或目标原本不在视口时，当前可读性优先，可缩短纠正时长；记录该降级，不承诺所有移动都以同样的缓慢速度完成。

### 5.4 换行与返回

- 普通相邻换行：按阅读带决定是否归位，新系统完整可见并不是跳过归位的充分条件。旧动画尚未完成时，检查新目标并平滑接管，不能造成位置跳变。
- 非相邻前向导航：保守地只保证实际目标可见，不预览中间未演奏系统。
- 原谱反复、Loop、seek/reset：取消归位、清空前进阶段状态，调用保留的传统导航定位逻辑。在返回后的同一系统内不要立即二次归位；下一次真实普通换行再启用新策略。
- Loop 中 reset/update/scroll 早于下一轮正式事件的场景必须覆盖，防止拿旧事件的系统把画面又拉回来。

## 6. 动画与生命周期

- 普通传统跟随使用一个自有 rAF 序列更新 scrollTop；更新目标不追加并行动画，不对每个音符调用原生 smooth scroll。
- 使用第 5.3 节确定的有限动画时长，保存稳定起点、目标、开始时间与 D，通过 elapsed time 计算插值；不能每帧重设起点或开始时间。到时收敛到目标并停止，无目标时不常驻空转。
- retarget 从当前实际位置接管，不能写回旧起点；尽量避免快速连续换行反复急停。页面挂起取消动画，恢复时重新评估，不把长时间帧间隔作为补播滚动。
- 先完成系统目标策略再调动画参数，不能用极慢滚动掩盖错误目标。
- 横向现有 33% 目标和 90 ms 参数保持原样；优先为传统新增独立状态，不顺便重构横向实现。
- `cancel()` 必须取消本组件拥有的两种动画；暂停、关闭跟随、布局切换、换谱、销毁及页面挂起不留旧帧。
- 保留旧返回分支时，验证原生 smooth scroll 与新 rAF 不会同时写 scrollTop；必要时在接管前终止旧滚动，并以当前实际位置为起点。
- reduced-motion 下跳过新动画，直接应用相同的阅读带目标及安全约束。
- wheel/touch 保留用户优先的取消行为。第一版不增加自动恢复计时器或新的设置；无新正式事件时不能因帧循环重新抢回视口。
- 跟随重新开启时，应在传统模式也执行一次当前位置检查并允许归位；播放恢复可从当前位置完成被暂停的归位。现有 `follow()` 为横向专用，不能简单把它改成双模式后让横向刷新回调误触传统导航。
- 重排时取消旧帧、更新几何，并清除旧系统身份；若当前位置仍可见，不强制归零或对齐顶部。若不可见，作一次必要纠正。
- 不用 CSS transform 平移整个原谱伪装滚动，避免点击、反馈、高亮与 SVG 坐标脱节。

## 7. 分阶段执行

### T0：复现并建立基线

1. 阅读上述模块，核对本地 `AGENTS.md`（若有）和开发文档，记录 Git 状态。
2. 执行 `npm run check`，记录真实基线；已有失败与本次引入的失败分别报告。
3. 准备至少四个系统的钢琴谱，设置一个恰好完整容纳两系统的视口，记录当前换行 scrollTop 轨迹和短录屏或截图序列。
4. 记录同谱同尺寸下系统数量、各系统包含的小节及主要边界，作为排版不变的基线。

### T1：系统几何和目标策略

1. 增加最小系统查询与布局版本缓存，验证 CSS px 转换。
2. 实现阅读带归位策略和只读的本行时长估算，核对速度单位、倍率与多声部时值，增加下节所列单元测试。
3. 保持现有传统入口可运行；不要在这一阶段改动音乐推进。

### T2：接入传统跟随

1. 接入一致的显示快照与前进/导航分类。

## 8. 验收与测试

### 8.1 单元测试

- 进入已经完整可见但低于阅读带的第二系统：启动归位，目标处于安全可见区间内，正常情况下顶部落在约 30% 处。
- 进入的新系统已在阅读带且完整可见：保持位置。顶部已高于阅读带但仍安全时，不为居中倒退。
- 同系统音符推进、同一快照重复调用：目标与开始时间不变；归位完成后不漂移、不另起预览动画。
- 当前系统不可见：必要纠正正确；系统较高时安全边界优先于 30% 目标。
- Follow / Realtime 拍数相同而速度不同：预计时长与 D 按公式改变且受限；速度相同而实际时值不同：结果相应改变。横向谱宽不同而时值相同：D 不变。
- 多声部、弱起、拍号和速度变化、速度倍率、跨行延音：估算不重复累计或混淆单位；非法或缺失数据回退固定时长。
- Wait 时长不受设定 BPM 影响；换行后完成唯一一段动画，后续等待不继续滚动。
- 两系统无法同时显示、单系统过高、第一页、末页、无下一系统、缺失几何：均有明确结果，无 NaN、死循环或上下抖动。
- 同系统反复、跨系统反复、Loop、seek/reset 可返回，不被前进目标约束阻止。
- 缩放与页面偏移下坐标正确；旧 layout revision 的系统几何不能继续使用。
- 动画有限时间收敛；不同刷新率下相同 elapsed time 得到近似位置；同一事件不重置截止时间。
- 连续换行只保留一个纵向帧序列，从实际位置接管，无旧目标队列；暂停、取消、销毁后无迟到写入；reduced-motion 无动画。
- 横向既有单元测试继续通过。

### 8.2 真实 OSMD 集成测试

| 场景 | 必须观察的结果 |
| --- | --- |
| 两系统完整可见，第一行进入第二行，第二行低于阅读带 | 换行后开始平缓归位，不等到第二行后半段；新行未被提前裁掉，正常条件下结束时顶部位于 25%～35% 区域 |
| 新系统已在阅读带且完整可见 | 保持位置，无细碎居中调整 |
| 当前系统已完成归位，继续演奏到行尾 | 无额外自动上移或提前启动下一行归位，允许约 1 CSS px 测量误差 |
| Wait 停在同一事件 | 动画收敛后持续等待至少 1 秒，位置保持稳定 |
| 暂停于动画中 | 取消后的帧不再改变 scrollTop；恢复后目标合理 |
| Follow / Realtime 连续推进，多组速度与行内拍数 | 实测 D 与估算及上下限相符，不重启动画，当前音符与反馈对齐 |
| Wait 使用不同设定速度，换行后停止输入 | 固定归位时长一致；完成后等待不漂移 |
| 极短系统连续换行 | 未完成动画由最新系统接管，无旧动画积压，不拖延音乐事件 |
| 整行长音或稀疏音符 | 真实换行触发后无需更多音符也能完成本次归位；不自行切到下一系统 |
| 双谱表、歌词/力度、加线音、不同系统高度 | 当前所需内容完整可见，几何降级不会抖动 |
| 50% / 100% / 150% 缩放，resize / 全屏 | 排版由原 OSMD 处理，跟随几何更新，无旧动画拉回 |
| 多个 SVG 页（若本项目当前支持） | 页偏移正确，跨页定位无坐标混用 |
| 反复与 Loop，含 count-in | 仍回到原位置，播放与判定不变，无新动画抢回旧位置 |
| 跟随关闭/开启、wheel/touch | 关闭后无自动移动；开启正确检查传统当前位置；人工操作能取消帧 |
| 传统与横向多次切换、换谱、销毁、页面挂起恢复 | 无旧帧、旧系统缓存或事件监听泄漏；横向行为不变 |

必须在至少一个测试中使用真正的逐事件播放路径，不要全部用 `seekMeasure()` 代替换行：seek 应走导航分支，不能证明普通演奏策略正确。

### 8.3 测量方法

- 受控 rAF 用于确定性断言；另用前台原生 rAF 验证实际运动。不能仅凭最终 scrollTop 正确就判定“平滑”。
- 记录时间、正式事件身份、系统 ID、Tline、D、归位起点、目标 scrollTop、实际 scrollTop，以及当前系统上下边界的屏幕位置。
- 正常尺寸且目标可达时，归位结束后当前系统顶部落在阅读带，随后保持稳定；首末页或高系统记录实际触发的边界降级。
- 用至少一段换行录屏或连续帧记录证明是平缓归位；同时测量动画实际持续时间，受控帧下应在 D 后一个帧间隔内到达目标。
- 普通前进动画不越过目标，不发生超过约 1 CSS px 的反向移动；排除明确返回、手动滚动和重排。
- 相同谱例、尺寸、zoom 下对比系统数量、小节所属系统和主要边界；通过可复现截图或 DOM 几何证明未改变原谱排版。
- 持续静止后帧数停止增长，不增加常驻计时器；频繁输入不导致整谱重新 render。
- 测试能力不足时明确写出缺口，不把未运行的浏览器/硬件检查记为通过。
