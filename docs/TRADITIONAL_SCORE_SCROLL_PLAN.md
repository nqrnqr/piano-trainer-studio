# 传统五线谱：随当前系统音乐进度上移

修订日期：2026-10-05。本次用户需求覆盖旧方案的冲突规则：删除换行后在 650～1200ms 内完整归位到 30% 阅读带的策略。执行与测量记录见 [traditional-scroll-results.md](testing/traditional-scroll-results.md)。2026-10-04 的独立复核和采样属于旧实现历史，不能作为本次体验验收证据。

后续用户反馈要求再靠上一点、移动稍快：停靠比例从可用高度 10% 调至 6%，目标推进完成比例从行内 65% 调至 60%，平滑响应从 180ms 调至 150ms；完整系统安全边界继续优先。

## 1. 范围

只调整传统模式的视口跟随。保留完整原谱、OSMD 原有换行分页、音符、加线、连线、力度和歌词。“一行”指整个 music system，钢琴高低音谱表一起判断可读性。

不展开反复，不复制乐句，不追加纵向 Loop 副本，不修改横向连续模式，不升级 OSMD，不添加运行时依赖。音乐事件顺序、音符判定、伴奏、节拍、计分和练习推进规则保持原有语义。原谱反复、D.C./D.S.、Loop、主动 seek/reset 仍沿用既有传统返回定位。

## 3. 行内进度与目标

1. 正式进入系统时记录实际 `scrollTop`、完整系统最终停靠位置和本次系统的时值区间。安全可见的系统不会在进入时开始一次完整归位。
2. 用实际事件间的时值累计已完成四分拍，再除以本次区间总拍数。一个 traversal 事件代表同时演奏的多声部一次，不能逐音符相加；不能用音符数量、小节数量、横向宽度或 BPM 推测进度。
3. 当前参数：在系统前 **60%** 的音乐进度内把滚动目标从入口位置推进至最终停靠位置，随后保持。60% 是可随真实谱例调优的体验参数。
4. 普通目标为 `入口 scrollTop + 上移距离 × clamp(音乐进度 / 0.60, 0, 1)`；另外取保证当前系统可读的最小必要移动。到达停靠后不再为了精确对齐而向下移动。
5. 后续同系统事件更新同一基准的目标，不重置起点、不叠加位移、不重新创建完整归位动画。重复通知不重建基准。
6. 反复或导航导致的回退清除旧基准。快速连续换行从实际位置建立新基准，最新系统接管唯一动画，不排队补播旧目标。

区间从真实入口到下一次离开系统、原谱返回或 Loop 上界为止；提前从系统中间进入、暂停恢复、人工操作后恢复跟随、重排时，从实际显示位置重建剩余进度基准。读取独立 trace 和现有 `getTraversalBeatsToWait`，包括弱起、休止、附点、连音、延音与跳转等待语义；最后事件复用播放的 fallback 时值。数据不可靠时只保证可见性，不自行推算音乐进度。

## 4. 三种模式

| 模式 | 推进依据 |
| --- | --- |
| Wait | 已提交且已正式绘制的事件。没有输入/正式事件变化时，只完成最后一次目标变化的平滑追随，再停止 |
| Follow | 同样以正式事件为准。设定 BPM 不推进目标；保留原有输入后延迟和休止推进规则 |
| Realtime | 正式事件累计拍数，加当前事件窗口内的拍数插值；窗口起止来自协调器已经用于播放调度的时刻，当前时刻来自既有播放时钟 |

Realtime 不新建音乐计时器或时钟。插值不超过当前正式事件窗口；窗口结束且没有新提交时，目标停止推进。长音与休止可在事件之间持续移动。暂停立即取消滚动；恢复重新读取实际位置和播放窗口，不能补播暂停前的轨迹。

`performancePosition.changed` 可能早于 `cursor.update`。视口在同步提交后的 rAF 中读取 painted 快照。只采用与 painted 的 score revision、trace index、小节和时间戳匹配的正式事件。协调器窗口身份在预取前保存，不能用已经预取的 live iterator 提前推进视口或换行。

## 5. 最终停靠与坐标

锚点是 **完整系统的图形上边界**，不是仅右手谱表或光标顶部。以旧版约顶部 10% 的最终位置为参考，但系统图形边界与光标边界不同，需要实测确认内容保护。

统一使用滚动容器内容中的 CSS px：

```text
margin = clamp(clientHeight × 0.04, 12, 32)
safeTop = max(margin, 工具栏在容器内的实际底边 + 4)
safeBottom = margin
usableHeight = max(0, clientHeight - safeTop - safeBottom)
dockScreenTop = safeTop + usableHeight × 0.06
最终 scrollTop = 系统图形 top - dockScreenTop
```

最终目标限制在合法滚动范围和整个系统的安全可见区间。若系统安全可见且已经处于目标或更靠上，保持当前位置。系统比剩余空间高时，完整系统可读性优先于百分比；容器根本无法容纳当前系统时，只做 painted 光标的最小可见性纠正，不能来回追逐两个无法同时满足的边界。

下一系统在空间允许时完整显示；不能为了凑两行而缩放、裁切或改排版。首末页、跨页或视口不足时自然降级。加线、连线、力度和歌词由 OSMD 系统图形边界保护，并以真实谱例验证。

geometry 使用该系统所属 SVG 页的 CTM，包含 zoom、页面偏移和容器边框，只转换一次。`clientHeight` 和 `clientTop` 必须与内容坐标一致。滚动不重建整谱索引；缩放、resize、全屏、重排、换谱和销毁失效缓存。

## 6. 平滑与取消

纵向只拥有一条可取消 rAF。其作用是平滑靠近不断变化的音乐进度目标，**不再保存整行归位截止时间**。

当前平滑参数为 150ms 指数响应，帧间隔最多取 50ms；距目标 0.5 CSS px 内精确收敛。这里的 150ms 只控制一次已提交目标的视觉追随，不决定整行音乐进度或整行移动时长。Wait/Follow 收敛后释放帧；Realtime 仅在当前有效窗口仍推进且尚未停靠时继续请求帧。

暂停、关闭跟随、wheel/touch、页面挂起、布局切换、换谱、重排和销毁取消旧帧，generation 防止迟到回调写回。用户手动滚动后，无新正式事件的重复通知不得抢回视口。再次启用跟随从实际位置建立基准。

旧版返回分支的原生 smooth scroll 与新 rAF 不能同时写 scrollTop。返回时保留原语义，建立进度基准但不追加一次系统边界纠正；下一次正常提交先终止旧滚动，再读取实际起点，并保留该基准已经完成的时值。reduced-motion 直接应用本次进度目标，不直接跳到整行最终停靠。

## 7. 验证与交付

删除所有固定 650ms、20% 行时长、30% 阅读带、同系统目标永不变化的冲突断言。必须覆盖：

- 当前系统未结束时已经上移；目标随实际时值进度变化，60% 后稳定。
- 完整双谱表及图形边界靠近顶部，下一系统在空间允许时完整可见。
- Wait/Follow 无输入不漂移；重复通知不累加、不重建；Realtime 长音插值与既有窗口一致。
- 不同速度、稀疏/长音、休止、弱起、多声部、连续换行、同系统及跨系统返回、Loop/count-in。
- 暂停恢复、手动滚动、开关、zoom、resize、全屏、重排、布局切换、销毁取消旧帧。
- 多页 CSS 坐标、安全边界降级、原谱布局和音乐判定不回归，既有横向测试继续通过。

执行适当单元测试、`npm run build` 和 `npm run check`。本地浏览器验收入口：

- `/docs/testing/traditional-scroll.html?led=off&music=native`：实际 OSMD、生产播放时钟/计时器、真实浏览器 rAF，通过实际播放与输入推进；仅隔离可听输出并简化 count-in 等待。
- `/docs/testing/traditional-scroll.html?led=off&frames=controlled`：受控音乐时钟和帧，用于可复现边界矩阵，不能替代前台原生轨迹验收。

轨迹记录原生时间、播放时钟、正式事件身份、painted/prefetched 位置、系统 ID、进度、滚动起点、当前目标、最终停靠、scrollTop 和系统屏幕上下边界。不能只检查最终 scrollTop，不能仅用 seek 模拟正常演奏。检查原生帧间隔以识别后台节流。
