# 横向连续乐谱独立复核

日期：2026-10-04

## 结论

本轮针对工作区中的横向展开实现进行代码审查和部分独立测试，没有发现可确认的阻塞问题。实现符合方案的核心方向：有限反复按实际演奏路径展开，练习 Loop 使用可重复的块地址继续向右显示，原谱与显示谱分离。

这是限定范围的复核结论，不代表已覆盖任意 MusicXML 导航组合或超长乐谱。

## 审查范围

- `performance-trace`、`performance-position` 和 OSMD adapter：独立遍历生成演奏路径，区分同一原谱音符在不同反复与 Loop 轮次中的出现；正式演奏位置与预取位置分离。
- `unfold-musicxml`、`source-note-index` 和显示 adapter：派生 MusicXML、音符结构映射、继承属性恢复及跨小节连接处理。
- `horizontal-chunks`、`horizontal-chunk-model` 和 `horizontal-score`：分段模板、缓存回收、坐标原点补偿、异步加载失效及销毁。
- services、播放协调器、点击定位、反馈和滚动跟随：核查显示坐标与原谱练习判定的职责边界，以及传统布局的接入路径。

源码中的资源上限为每块 8 个主要小节、最多挂载 7 个块、模板缓存最多 16 项。Loop 使用轮次计算地址，不按轮次无限保存模板。

## 验证边界

- 已阅读实现方的 `horizontal-unfolded-results.md` 及相关测试代码；其中 53 页、3,088 项浏览器断言是实现方记录，本轮未完整重跑，不能算作本轮独立实测结果。
- 为超过 16 个模板的长谱缓存淘汰和快速跨块推进准备了额外测试页，但浏览器工具访问该本地页面时返回 `net::ERR_BLOCKED_BY_CLIENT`。该测试没有执行完成，不能据此判断应用有故障，也不能声称这些场景已经独立验证。
- 本轮没有实测实体 MIDI 键盘、可听音频同步、触屏或真实浏览器往返缓存恢复。
- 有限谱准备仍需要计算各块宽度；复杂长连接可能扩大单块上下文。超长谱加载时间和连续滚动性能仍需用实际曲目验证。
- 实现方记录 OSMD 1.9.7 对 `repeat times="3"` 的次数支持有限。当前显示跟随实际演奏引擎路径；本次修改未解决这一既有 vendor 限制。

建议下一轮优先补测一份超过 128 小节的实际乐谱，覆盖首次准备、远距离点击、快速跨块推进、缩放，以及自动跟随关闭后重新开启。验收应观察当前音符高亮是否正确、是否出现空白块、自动回收前后音符屏幕位置是否稳定。

本轮未修改生产代码，未创建 Git 提交。
